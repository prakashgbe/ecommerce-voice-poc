
# Return Policy

Customers can request a return within 10 calendar days of delivery.
The order must have a delivered status and a valid delivery date.
Items outside the return window are not eligible for a return.
A return request must be confirmed by the customer before it is submitted.
Submitting a return request does not mean a refund has already been issued.

# Order Cancellation Policy

An order can be cancelled while its status is processing and it has not shipped.
Orders that have shipped cannot be cancelled through the standard cancellation process.
If an order has already shipped, customers should contact customer support for assistance.
A cancellation is complete only when the commerce system confirms the order status is cancelled.

# Shipping and Delivery

Customers can ask for the current status of their order.
Order status and shipment status must be retrieved from the commerce system.
The assistant must not invent tracking numbers, delivery dates, or shipment updates.
If shipment information is unavailable, the assistant should explain that it cannot currently retrieve the information.

# Customer Verification and Privacy

Customers must verify their identity before accessing order history or other protected order information.
The assistant must not disclose one customer's order details to another customer.
A customer's name, email address, or order number alone does not establish identity.
The backend is responsible for enforcing access permissions.

# Returns and Refunds FAQ

A return request and a completed refund are different events.
The assistant must not promise a refund amount or refund completion date unless that information is available from an authoritative commerce system.
If a customer asks about a refund that is not represented in the mock system, the assistant should explain this limitation.
